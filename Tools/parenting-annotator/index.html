Behavior categories

Rename or recolour freely: annotations are linked by the stable id, so a rename updates every annotation and is re-saved to each affected JSON. A category that is used by an annotation cannot be deleted. Training role is separate from the annotation category and only decides how build_reviewed_manifest.py maps it onto the model's two classes (other / ParentingAll): positive → ParentingAll, negative → other (explicit negative example), exclude → seconds with this label are dropped from training (Sniff / Attack / Retrieve in the existing pipeline), unmapped → not used until someone decides. Category definitions are saved to categories.json in the folder and in this browser, and restored when the annotator reopens.

Tracks: each behavior category has its own timeline row. parenting is the model's pooled prediction — reassign to Jie's BORIS codes as you review. Overlapping segments within a category split into sub-lanes so nothing collides.

Timeline extras: the grey shading marks time outside the analysis range; the green bar in the bottom strip marks reviewed ranges; when a <video>.scores.json file is present, the purple curve is the model's parenting probability with the threshold line and a dashed preview of the thresholded segments.

Annotations auto-save to the video folder as individual JSON files. The toolbar badge shows Unsaved / Saved / Save FAILED; unsaved edits are also kept in this browser and offered back when the folder is reopened.
